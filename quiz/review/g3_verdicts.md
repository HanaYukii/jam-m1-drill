## Notes

- Symbol drift, 0.7.x → 0.8.0. The three SUSPECT items are all the same class of defect and are the only ones: 0.8.0 fixes G = reporters (11.28), I = incoming reports (11.30), R = newly available reports (11.17), S = accumulation statistics (12.27). Items 126/127 use these correctly (their gpRefs even say "reporters set G", "11.17 (R), 11.30 (I)"), so 221–223 are internally inconsistent with the rest of the group. None of the three has a second defensible option, so the items still discriminate — but the keyed option teaches a wrong symbol.
- Header-field subscripts (cosmetic, no verdict impact). GP 0.8.0 renders header fields with upper-case subscripts: H_T (timeslot), H_I (author index), H_O (offenders marker) — eq. 5.1. Items 112 and 126/221 write H_t / H_i lower-case while 195 writes H_O correctly. Worth normalizing to H_T / H_I.
- ch10-report-hash-identity distractor A writes the work-package hash as "(w_s)_h"; in 0.8.0 the availability-spec field letters are (p, l, u, v, e, n) — the package hash is (w_s)_p and the segment root is (w_s)_e. The distractor names it in words too, so it is still clearly indefensible; only the letter is stale. (Distractor D's "(w_s)_u" for the erasure root is correct.)
- Bold/plain collision in eq. 9.3 (touches ch09-account-fields). The account tuple has both a_p (bold p = the preimage dictionary) and a_p (plain p = the parent service). Option B's "a_p — the parent service index" is true only under the plain-p reading; either way it is a real field, so the key (no nonce) is unaffected. Rendering the option as "a_p (parent service)" would remove the ambiguity.
- Genuine GP ambiguity, eq. 10.7. "r ∈ ψ′_B ⇔ r ∉ ψ′_G ⇔ v" is a chained biconditional. Read as mutual equivalence (all three agree — the standard GP reading, and the one every conformance implementation uses) a wonky r admits no fault and ch10-code-fault-equivalence-wonky's key is right. Read left-associatively, ((⊥⇔⊤)⇔⊥) = ⊤ would make the wonky+v=⊥ fault *valid* and option A the answer. The item is safe under the intended reading, but the stem could pre-empt the quibble by saying "all three terms must agree".
- Genuine GP defect, eq. 13.13 (touches ch13-service-stats). The provision term is written Σ_{(s, x) ∈ E_P} (1, |x|) with no restriction to the service s being defined — literally every service in s would get the whole block's preimage totals. Clearly a missing "where s = the preimage's service index" condition. The keyed option says only "provision (count, total size) from E_P", so it is unaffected either way.
- Statistics prose vs state, §13.1 (touches ch13-why-statistics). The "validators vote on each other's efforts / median" mechanism is prose only in 0.8.0 — the corresponding per-validator `u` counter is commented out of eq. 13.2, so the six-counter record carries no audit-activity field. The item asks what the GP *says*, so the key holds; the trap could note the field's absence.
